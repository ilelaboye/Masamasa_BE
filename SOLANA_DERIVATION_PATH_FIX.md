# Solana Derivation Path Fix - Phantom Wallet Compatibility

## Problem
The Solana master wallet address generated by the backend didn't match the address shown in Phantom wallet when using the same mnemonic phrase.

## Root Cause
Different derivation paths were being used:
- **Backend (before fix)**: `m/44'/501'/0'/0'/0'` (5 levels)
- **Phantom wallet**: `m/44'/501'/0'/0'` (4 levels - standard BIP44)

## Solution
Updated `getMasterKeypair()` method in `src/modules/web3/sol-hd-wallet.ts` to use Phantom's standard BIP44 path.

### Changed Code
```typescript
// BEFORE (incorrect - 5 levels)
getMasterKeypair(): Keypair {
  return this.deriveKeypair(0, 0, 0);  // Generated: m/44'/501'/0'/0'/0'
}

// AFTER (correct - 4 levels, matches Phantom)
getMasterKeypair(): Keypair {
  const path = `${SOL_DERIVATION_PATH_PREFIX}/0'/0'`;  // Generates: m/44'/501'/0'/0'
  const derived = derivePath(path, this.seed.toString("hex"));
  return Keypair.fromSeed(derived.key);
}
```

## Derivation Path Structure

### Master Wallet
- **Path**: `m/44'/501'/0'/0'`
- **Usage**: Receives all swept funds from child wallets
- **Standard**: Matches Phantom wallet's default account
- **Method**: `getMasterKeypair()`

### Child Wallets (Regular Users)
- **Path**: `m/44'/501'/0'/0'/index'`
- **index**: User ID (e.g., 1, 2, 34, etc.)
- **Usage**: Individual user deposit wallets
- **Method**: `deriveKeypair(userId)` where userId = 1 to ~1,000,000
- **Example**: User ID 34 → `m/44'/501'/0'/0'/34'`

### Disposable Wallets (Temporary)
- **Path**: `m/44'/501'/0'/0'/index'`
- **index**: Starts at 1,000,000+ (avoids collision with user IDs)
- **Usage**: Temporary wallets with expiration
- **Method**: `deriveKeypair(index)` where index >= 1,000,000
- **Example**: First disposable → `m/44'/501'/0'/0'/1000000'`

## No Collision Between Wallet Types
- Master: `m/44'/501'/0'/0'` (4 levels)
- Users: `m/44'/501'/0'/0'/1-999999'` (5 levels, low indices)
- Disposable: `m/44'/501'/0'/0'/1000000+'` (5 levels, high indices)

## Impact

### ✅ No Breaking Changes
- Master wallet address is now correct and matches Phantom
- Child wallet paths remain at 5 levels (no collision with master)
- Disposable wallet paths remain at 5 levels with high indices
- All existing functionality continues to work

### ⚠️ Important Notes
1. **Master wallet address has changed** - If you had funds at the old master address, you'll need to sweep them manually to the new correct address
2. **Child wallet addresses are unchanged** - They still use 5-level derivation paths
3. **Mnemonic security** - The same mnemonic controls ALL wallets (master + all children)

## BIP44 Standard Reference
According to BIP44 standard for HD wallets:
```
m / purpose' / coin_type' / account' / change / address_index
```

For Solana (coin_type = 501):
- **Standard account**: `m/44'/501'/0'/0'` (what Phantom uses)
- **With address index**: `m/44'/501'/0'/0'/index'` (what we use for child wallets)
